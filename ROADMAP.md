# Roadmap

The initial release prioritizes the thirty-item working MVP. The roadmap is not a list of capabilities being advertised as live.

## Phase 1 — Core foundation: implemented

- FastAPI, React/TypeScript, SQLite, SQLAlchemy and Alembic.
- Provider contracts, deterministic demo data, explicit provenance and freshness.
- Causal features, configurable score weights, lifecycle/anomaly/early-signal rules.
- Dashboard, universal catalogue search, watchlist, reports, CLI and Docker configuration.
- Tests, CI, state-preserving daily schedule and security checks.

## Phase 2 — Initial domain sources: adapters implemented

- Financial daily OHLCV, raw YouTube public-video statistics and public GitHub snapshots.
- Financial technicals and asset-level rule regime.
- Required before claiming live coverage: credentials, provider contract checks against real responses, target-environment deployment tests and data licensing review.
- Next: licensed news ingestion with deduplication, adjustment/corporate-action data, exchange calendars and primary/secondary feed reconciliation.

## Phase 3 — Search, fashion and historical intelligence: partial

- Implemented: non-overlapping historical analogue engine; synthetic search/fashion examples.
- Next: approved search/retail adapters, event contexts supported by actual sources, semantic aliases/novelty/clusters, credible geography normalization and multi-source confirmation.
- No Google Trends scraping workaround is planned.

## Phase 4 — Forecast evaluation: research tools implemented

- Implemented: conservative multi-horizon baseline, immutable audit/outcomes, retrospective walk-forward, reliability bins, offline logistic/RF/gradient-boosting comparison, chronological calibration utilities, lead–lag explorer and promotion gate.
- Next: sufficient real prospective outcomes, model-specific held-out calibration, return-conditioned/regime uncertainty, independent candidate holdouts and drift monitoring.

## Phase 5 — Advanced inference: research backlog

- Full event/evidence relationship graph, approved geography data, causal study designs and robust seasonality models.
- Deep models only after improving locked walk-forward and prospective baselines.
- No certainty claims, broker execution or confidence inflation.

## Phase 6 — Community and scale: partial SDK

- Implemented: opt-in installed provider entry points.
- Next: stable scorer/model plugin contracts, community provider conformance suite, persistent relationship graph, advanced visualization, multi-user authorization, shared rate limits and optional PWA shell with explicit stale-value handling.

## Exit criteria for a stronger release

Real-data access tested, meaningful prospective samples retained, calibrations measured on separate holdouts, model promotion reviewed, migrations tested against PostgreSQL, source policies enforced in deployment/backup flows, accessible browser paths verified and limitations updated honestly.
